# grid_whatif

# ⚡ Цифровий двійник мережі 10 кВ: «Що, якщо?» та прогноз відмов

Streamlit-застосунок для диспетчерів і служб експлуатації розподільчих мереж. Поєднує сценарний аналіз аварій (N-1 / N-k) та прогнозування відмов обладнання (Predictive Maintenance).

> ⚠️ **Усі дані в демо синтетичні.** Застосунок показує підхід і не призначений для оперативного керування реальною мережею без адаптації та валідації.

## Можливості

### 🔥 Сценарний симулятор «Що, якщо?»
- Вибір одного чи кількох елементів (ПС, ТП, лінія), що виходять з ладу (сценарій N-k).
- Умови режиму: температура, година доби, температурна чутливість навантаження, потужність ПС, допустиме перевантаження.
- Розрахунок потоків по лініях та навантаження ПС.
- Автоматичний пошук перемикань: ізоляція пошкодження та відновлення живлення через нормально-розімкнені перемички.
- Графік обмежень (ГОП) за пріоритетами споживачів, якщо перемикань недостатньо.
- Карта схеми у трьох станах: норма, одразу після аварії, після перемикань.
- KPI: МВт без живлення, кількість споживачів, недовідпуск (ENS), SAIDI сценарію, максимальне завантаження.
- Покроковий протокол перемикань з часом кожної дії (експорт у CSV).
- Теплова карта чутливості «температура × година».

### 📚 Бібліотека протоколів N-1
Розрахунок для кожного елемента мережі, рейтинг за критичністю, експорт усіх протоколів в один CSV. Диспетчер має готові дії заздалегідь.

### 🔮 Прогноз відмов (Predictive Maintenance)
- Модель `GradientBoostingClassifier` оцінює ймовірність відмови кожного ТП, ПС і лінії.
- Ознаки: вік, середнє й пікове завантаження, години перевантаження, холодний режим, попередні відмови, час від останнього ТО, індекс стану (ХАРГ / тепловізор / ЧР), тип активу.
- Налаштування горизонту (1–24 міс.), приросту навантаження та кількості «холодних» днів.
- Категорії ризику (Критичний / Високий / Середній / Низький) та рекомендації.
- Пояснення, які фактори найбільше впливають на ризик конкретного активу.
- Можна завантажити власну історію відмов у CSV.

### ⚖️ Ризик = P × наслідки
Об'єднує ймовірність відмови з наслідками для споживачів (ENS, SAIDI) зі сценарного симулятора. Результат: матриця ризику, реєстр пріоритетів і готовий протокол для найризикованішого активу.

## Як це працює

**Мережа.** Радіальна схема: 2 ПС 110/10 кВ, 4 фідери, 20 ТП, 6 нормально-розімкнених перемичок. Потік на кожній лінії дорівнює сумі навантажень усіх ТП нижче за течією.

**Навантаження.** `P = P_ном × профіль(година) × (1 + k × max(0, 5 − T))`, де `k` — температурна чутливість (%/°C). Профіль зимовий, пік о 18:00.

**Відновлення живлення.**
1. Пошкоджений елемент ізолюється (відкриваються комутаційні апарати навколо нього).
2. Знеструмлені ділянки (острови) сортуються за важливістю.
3. Для кожного острова перебираються перемички до живої частини мережі. Обирається варіант з мінімальною зваженою втратою навантаження (вага за пріоритетом споживача: 10 / 3 / 1).
4. Якщо виникає перевантаження, відключаються споживачі з найнижчим пріоритетом.
5. Острів не відновлюється, якщо це збільшує зважені втрати.

**Показники.** ENS = Σ (P × тривалість переривання). SAIDI сценарію = Σ (споживачі × хвилини переривання) / загальна кількість споживачів. Відновлені перемиканнями ТП мають тривалість до моменту комутації, решта — тривалість ремонту.

**Прогноз відмов.** Імовірність за горизонт: `1 − (1 − p_рік)^(міс/12)`. Ризик для пріоритезації: `P × ENS`.

## Підключення реальних даних

| Що замінити | Чим |
|---|---|
| `build_grid()` | Топологія, навантаження ТП, перерізи/ліміти ліній із ГІС, SCADA, АСКОЕ |
| `static_registry()` | Реєстр обладнання: вік, відмови, дата останнього ТО, результати ХАРГ/ІЧ/ЧР |
| `make_training()` | Історія відмов із системи ЕАМ/CMMS (або завантаження CSV на вкладці прогнозу) |

Формат CSV для навчання: стовпці `age, loading_mean, loading_peak, overload_hours, cold_hours, prior_faults, years_since_maint, condition_idx, is_tp, is_ps, is_line, failed` (`failed` = 0/1: відмова протягом року).

## Обмеження

- Спрощений розрахунок радіальних потоків (потужності без струмів, напруг і втрат).
- Не враховується реактивна потужність, РЗА, розподілена генерація.
- ML-модель навчена на синтетичних даних; для практики потрібне навчання та перевірка на реальній історії.
- Час комутацій і ремонту задається середніми значеннями.
